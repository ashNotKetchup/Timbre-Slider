How much each attribute is encoded
predicted from one latent frame, on clips the predictor didn't see

        

        
Generative latent: a linear predictor from one frame of the generative model's latent to the attribute, trained on the other clips (k-fold by clip). This is the informativeness score of the DCI framework [1]. R² needs the right values; rank r (Spearman) needs only the right order, which is all the ranking loss asks for. Within clips is the median rank correlation inside each clip, which is what matters when editing one sound. Between clips ranks the clip averages.

        
After the VAE: the same predictors applied to the latent after the full VAE round trip (encode, then decode). A drop means the VAE loses that attribute. VAE code: predicted from the VAE's own code instead. The VAE was trained on every clip's labels, so this column is optimistic.

Sliders edit within one sound. An attribute that mostly varies between clips teaches the VAE how sounds differ, not how one sound changes, so its slider can end up moving other attributes too.

Method and references
          
All numbers use the frames the backend trained the VAE on (from prepare_data), standardised as the VAE sees them, with the duplicate of the sample that run_server appends removed. Predictors are ridge regressions held out by clip, so a clip is never scored by a model that saw it.

What each slider does
change in each attribute over the slider's full travel, std units

        

        
Each slider is moved from −2 to +2 times its spread (its std over the folder's frames), from 400 frames across the folder, and the edit is applied by delta decoding as in the app. The attributes of the result are re-measured with the folder's latent-to-attribute predictor, which stands in for decoding to audio and running the feature extractor (the Dataset tab shows how far to trust it). Medians over frames. This is the latent traversal used to evaluate attribute-regularised VAEs [2, 9]. Gain: change in the slider's own attribute (for an unregularised dim, the attribute it moves most). Selectivity: that change as a share of the change in all attributes. Monotonic: median rank correlation between slider position and the attribute, per frame (1 = always rises).

Path through the generative latent
the slider's edit followed into the 64-dim latent the generative model decodes

        

        
Speed: latent distance moved per unit of slider (the decoder's magnification along that direction [5]). Path ÷ straight line: length of the decoded path over the distance between its ends; 1 means the slider moves in a straight line, higher means it curves [6]. End-to-end turn: cosine between the path's first and last steps (1 = same direction, 0 = a right angle). Unevenness: variation of step size along the path (0 = the sound changes at a steady rate), in the spirit of perceptual path length [7]. Distance to seen sounds: distance to the nearest real frame in the folder, ignoring the frame's own moment, in units of the typical gap between real frames [8]; above about 1.5 the slider is taking the sound somewhere the folder has nothing like.

      


      

        
Landscape
the folder's frames in 2D, with one slider's paths from moments of the sample

        

          
          
          
          
        

        

        
Dots are frames of the folder, coloured by an attribute's measured value. The grey line is the sample over time (smoothed). Each arrow is the selected slider moved from −2 to +2 spreads from one moment of the sample, with a dot at the unedited point. Attribute views place frames and paths alike by the attributes the predictor reads from the latent, so an arrow that runs along the x axis moves that attribute and nothing else. Latent PCA places them by the two main directions of the generative latent; it keeps only the variance in the axis labels, so treat lengths as rough. Arrows that leave the cloud are edits the folder has no examples of. These maps follow the surface and density plots used to explain generative music latents [9, 10].

      


      

        
Disentanglement scores
VAE code against the attributes, all frames

        

        
SCC: best rank correlation between the attribute and any single dim, and which dim [2]. MIG: gap in mutual information between the two dims that share most with the attribute, over its entropy [3]. SAP: gap in R² between the two dims that predict it best on their own [4]. Completeness (one dim captures the attribute) and disentanglement (each dim captures one attribute) from DCI, with linear-regression importances; informativeness is R² from the whole code on held-out clips [1]. The VAE was trained on these labels, so these describe the fit, not generalisation.

      


      

        
Method and references
          
Traversals, paths and the landscape use the trained VAE on the CPU and the folder's own frames; nothing here decodes audio. Re-measuring attributes uses a ridge regression from a latent frame to the attributes, fitted on all the folder's frames.
